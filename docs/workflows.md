# Clinic Growth System — Product Workflows

## A. Internal company workflow

Derived from the operating plan:

**Research market → identify prospect clinics → build clinic record → audit clinic → identify growth problems → prioritize → outreach → conversation → clinic audit → proposal → close pilot → onboarding → delivery → case study → decision gate.**

This reflects the PDF's Week 1–4 execution sequence.

## B. Clinic growth workflow

**Discovery → enquiry → booking → attendance → revenue → retention → referrals.**

## C. Proposed product workflow for the prototype

This is our current product interpretation, not a direct quote from the PDF:

1. Clinic is onboarded.
2. Clinic profile and operating baseline are recorded.
3. Growth gaps are captured from the audit.
4. New enquiries enter the system.
5. Enquiry is assigned to AI and/or staff.
6. Enquiry is qualified.
7. Appointment is booked or staff is asked to intervene.
8. Follow-up/reminder workflow runs.
9. Appointment outcome is recorded.
10. Review / retention / referral workflows become available.
11. Dashboard reports funnel and commercial metrics.

## D. Safety workflow for future AI actions

Before real automation:

**AI proposes action → policy / permission check → validate context → execute approved tool action → log outcome → human escalation when required.**

This is a future engineering design based on the project's compliance requirements; it is not explicitly specified as an AI architecture in the PDF.
